## 二、如何「验证效果」—— 三个层级

### 层级1：快速自检（不依赖 AutoTest，只需 Python）
用模拟器判断每关是否可解（复刻 AutoTest 走棋逻辑）。
```bash
cd generator
python3 test_control.py          # 判别力对照（可解/不可解）
python3 test_real.py ../levels.json 1,2,4   # 用真实关卡校准模拟器
# 自检 generated_levels.json 全部可解：
python3 -c "
import sys,os,json;sys.path.insert(0,'.')
from autotest_sim import solvable
from test_real import build_board as bb
d=json.load(open('generated_levels.json'))
ok=sum(1 for lv in d['Levels'] if solvable(bb(lv))['solvable'])
print(f'可解: {ok}/{len(d[\"Levels\"])}')"
```
- **完全可解** → 通过；有不可解 → 调整生成参数/种子重新生成。

### 层级2：结构校验（字段/配额合法）
```bash
python3 -c "
import json;d=json.load(open('generated_levels.json'))
print('字段完整:',all(set(['LV','HardType','Grid','Parks','PayParks','Cars','Entities','Emptys','Factorys','Boxs','LockDoors','SubLevels','GridLocks','GridKeys','FreezingCars','TotalCarColorTypes','TotalCarCounts']).issubset(lv) for lv in d['Levels']))
print('每色3倍数(可全消):',all(all(c%3==0 for c in lv['TotalCarCounts']) for lv in d['Levels']))
print('每个元素10字段:',all(all(len(e)==10 for arr in ['Parks','Cars'] for e in lv[arr]) for lv in d['Levels']))"
```

### 层级3：【权威】AutoTest 真实验测（唯一可信标准）
AutoTest 按策划走棋规则判定「是否胜利 / 剩余青蛙数 / 操作次数」。这是策划认可"可玩"的真实标准。

## 三、如何「实际测试」（AutoTest 实跑闭环）

### 前置：授权（一次性）
macOS 系统设置 → 隐私与安全，给 **Terminal**（运行 Harness 的宿主）授权：
1. **辅助功能**（系统事件/鼠标操控）
2. **屏幕录制**（窗口截图定位坐标）

授权后，若改了关卡文件，见下面的"重要机制"。

### 一键闭环脚本
```bash
cd generator
# 把生成的关卡放入 AutoTest 读取目录，并跑测试（读 GameLog.txt 结果）
# 用法: python3 run_validate.py <levels.json> ；或自动跑整关:
python3 drive_autotest.py 1 50    # (激活AutoTest -> 填 1..50 -> 点自动测试 -> 读结果)
```

`drive_autotest.py` 会自动：激活 AutoTest 窗口 → 填「开始关卡id / 结束关卡id / 次数」→ 点「自动测试关卡」→ 读 `GameLog.txt` 的每关 `是否胜利 / 剩余/步数`。

### 结果判读
- `是否胜利:True` → 该关可玩。
- `是否胜利:False` + `失败原因:停车位已满且当前停车表无可消除车辆` → **该关不可玩**（每种颜色凑不齐3只，荷花占满但无三连）。需重新生成。
- `失败原因:连续5次轮询无可执行车辆` → 青蛙卡死（通道被堵）。需调整布局。

---

## ⚠️ 重要机制（易踩坑）

1. **改关卡文件后必须重启 AutoTest**：`DummyLevelProvider.uc()` 只在进程启动后**首次加载一次**关卡（`fiz` 缓存）。每次改 `levels.json` 后，需重启 AutoTest（`pkill -f "Frog Match"` 再 `open AutoTest.app`），新关卡才生效，否则新加的关报"读取关卡失败"。
2. **正确批量流程**：先写好整批关卡 → 重启 AutoTest → 一次测完整批。

## 四、已用到的关键模块（generator/）

| 模块 | 作用 |
|---|---|
| `generator2.py` | **主生成器**：槽式静态青蛙布局 + 难度档位 + 可解性自检（推荐首选）|

| `generator3.py` | Factory+Box 生成器（见"已知结论"，当前随机布局**不可玩**，仅作探索）|
| `random_car.py` | RandomCarManager 颜色分配复刻 |
| `rules.py` / `solver.py` | 数据模型 / DFS 求解器 |
| `drive_autotest.py` | **GUI 一键闭环**（激活→填值→点按钮→读结果）|
| `run_validate.py` | 写关卡到 persistentDataPath + 读 GameLog |
| `test_control.py` / `test_real.py` | 判别力对照 / 真实关卡验证 |

## 五、已验证结论（重要）

1. **静态青蛙关（generator2 + 难度梯度）→ 可靠可玩**：High 难度 20/20、50/50 全胜（AutoTest 实测），模拟器自检可解。
2. **Factory/Box 随机布局（generator3）→ 不可玩**：AutoTest 实测约 15/16 失败，根因是 `停车位已满且当前停车表无可消除车辆`——运行时随机刷的颜色**凑不齐 3 连**。**真实关卡的 Factory/Box 是设计师精心设计的可解迷宫，无法靠随机布局保证可玩**。若要运行它，需改为"从 500 关模板抽取真实布局微调"或复杂约束求解，非本阶段范围。
3. 生成器优先选**已验证可靠的静态青蛙关**；Factory/Box 仅作为探索模块保留。
