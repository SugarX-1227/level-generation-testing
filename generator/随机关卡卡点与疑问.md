# 随机(非静态)关卡生成 —— 卡点与疑问清单

> 配图背景：关卡455(含 Factory/Box/"?"格) 生成/验证随机关卡时，卡在"可解性"。
> 已用 AutoTest 实测：**真实关卡455 跑8次，胜率 2/8 = 25%**（剩余 20~44 只），证明**青蛙颜色运行时随机，非预置**。

---

## 一、为什么"随机(非静态)关"的卡点集中在可解性

**核心事实**：Box(?"格)/Factory(出口格) 开出的青蛙**颜色由 `RandomCarManager.om()` 按 `TotalCarCounts` 配额运行时随机生成**（反编译确认），且同一关每次跑结果不同（实测455）。

**所以区别于静态关**（颜色预置→必解精确保证），非静态关的可解性是**概率性**的——游戏本身允许某局解不出（多试几局）。设计者能定的只有 **结构 + 配额 + Space概率**，求的是"提高胜率"，不是"保证必解"。

---

## 二、生成随机关卡的卡点（按影响排）

1. **【最卡】可解率无法从生成端保证/预测**
   - 青蛙颜色运行时随机，生成器无法预知某关具体出哪些色。
   - 我能保证 `ol()` 等式 + 每色3倍数 + 通道合法，但这**只是"不物理堵死"，不等于"能凑成3连消除"**。
   - 已实测：我 generator3 生成的关 AutoTest 约 15/16 失败；连真实455 也只有25%。**说明"布局合法"远未达到"可玩"**。

2. **【关键，未完全还原】`levels_probability`(Space概率) 如何真正影响可解率**
   - 表：`Space7=0, Space6=0.1, Space5=0.3, Space4=0.3, Space3=0.4, Space2=0.5, Space1=0.5`。
   - 空间空(7)时概率=0，空间紧(1)时概率=0.5 —— 意图是"空间紧张时强倾向凑3连防堵死"。
   - **但我用该表模拟 `om()` 刷蛙填荷花，结果全部判负**（刷7只就占满无3连）。说明我**没完全复刻真实游戏的"凑3连/落位/消除"时序**，或 Space概率的作用点理解有误。这是当前最大技术缺口。

3. **【缺数据】真实关卡胜率的分布未知**
   - 只测了455(25%)。不知道真实500关里含Factory/Box的关卡**平均胜率多少**、是否有的关能到80%+、靠什么参数达到。
   - 没有"可解率基线"，就无法校准我的生成器该调到什么水平才算"合格"。

4. **【机制不完整】Box / Factory / SubLevel(?"格) 的出蛙与遮挡细节**
   - Box=`IncludeCarCount` 多另为0，但确实出蛙 → 出蛙数/颜色到底由什么决定？(实测是运行时 random，但生成时"每格出几只"的字段机制未完全摸清)
   - SubLevel(`Floor=1`,`SubLevelSizeX*Y`) 藏蛙、揭开才见，其内青蛙数/色来源待确认。
   - 遮挡格"?"的**显示数字n** 与 `IncludeCarCount` 的对应关系未完全确认。

5. **【评估手段繁琐】AutoTest 只能测胜率，且需多次跑**
   - 单关需 `count` 参数跑多次才得胜率；每次要重启 AutoTest(改文件后)。
   - 不能批量、快速评估一大批生成关的可解率。

## 三、具体疑问（待你/团队确认）

1. **?格/出口格的青蛙颜色，到底能不能在数据里预置为固定颜色？**
   - 我反编译+b实测是"运行时随机"(455=25%，每局不同)。
   - 若你们实际做关能预置固定色 → 那非静态关可做成"必解"(像静态关)。
   - 若确实只能运行时随机 → 就用"胜率"标准验收。
   - **这是最关键的一个确认。**

2. **你们内部做这类关时，靠什么保证"大多能解"？**
   - 是手工反复试 + 看胜率到一个阈值？还是有个"可解性校验工具"？
   - 阈值大概多少(比如≥80%)算合格？

3. **`levels_probability`(Space概率) 到底怎么用/谁能帮我确认**？
   - 每关可单独配(id行)，还是只有前48关有定制、其余默认？
   - 提高"空间紧时凑3连概率"能不能显著提高胜率？（这是我唯一能想到的可解率旋钮）

4. **真实500关里，含Factory/Box的关卡平均胜率是多少？** 能否给我几关"公认好解/难解"的例子做基线对照？

5. **"?"格数字n 的准确含义**：是"该格会放n只青蛙"还是"翻开一次出n只"？Box 与"?"格是不是同一实体？

6. **你们想要这类关的最终标准**：是"结构像真实 + AutoTest胜率≥某阈值"，还是"只要结构合法、胜率交给玩家多试"？
